## 基线结论

- 首次服务端聚合耗时过长，并已出现 EdgeOne Cloud Function 503。
- 查询参数会生成动态页面请求，四个入口无法稳定复用同一份页面结果。
- dashboard API 使用时间戳和 `no-store`，会强制绕过共享缓存。
- 球员和数据入口仍有较大的初始 RSC 负载；第三阶段 A 优先解决服务端超时，负载拆分留给专用 read model/RPC 阶段。

## 本阶段目标

- 数据库聚合结果在同一云函数实例的请求之间共享，并合并并发刷新，避免每个访问者重复执行完整 REST 链。
- 使用 Edge/CDN 的 `stale-while-revalidate` 和 `stale-if-error`，数据库短暂抖动时继续返回最近成功数据。
- 实时比赛维持 30 秒更新；近期数据 5 分钟；球员资料 1 小时；历史数据 24 小时。
- 上线后使用同一采样方式记录对照数据。
